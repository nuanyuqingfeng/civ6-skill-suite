# 跨会话交接模板（civ6-model-import）

交接失败只有一种形式：接手方从头试错。模板的目标是让接手方跳过全部已证伪路径。

## 交接文档六要素

```markdown
# <任务名>交接（<日期>）

## 一、当前状态与唯一正确基准
- 当前可行版本的部署指纹：BLP 字节数 + sha256 前 16 位
- 「正确」的判定来源：哪一次实机观察、谁确认、截图位置
- 当前工程 git 状态：入库范围、最近提交哈希
- 表情数据链路线判定：A / A2 / B-授权编号 / ABSTAIN（`expression-route.md` §四）

## 二、已修复不必重做清单
逐条列已解决问题 + 修复方式 + 验证证据（文件:行号 或 指纹）。

## 三、已被推翻的旧结论（防复读）
逐条列「曾经认为是根因或可行路径，后被实测推翻」的判断 + 推翻它的证据。
接手方读到旧文档里的这些判断时，以本节为准。

## 四、困境与待裁决
- 当前无法推进的问题（带已排除项清单：排除过程与证据）
- 等用户决定的选项；已发生的询问记录（触发原因 + 答复原文 + 判定）必须原样保留

## 五、建议路线（按性价比排序）
每条路线注明：预期收益、前置条件、验证方式。

## 六、可复制接手提示词
一段可直接粘贴给新会话的完整提示词，含：任务边界、必读文件清单（按读取顺序）、
环境要点、硬约束（判据闸门、禁止事项）、交付形式。
```

## 接手方第一动作

1. 核对基准指纹是否仍成立（部署位与文档指纹比对）。
2. 按「四、困境」节的已排除项清单自查环境差异（盘符、版本、残留产物）。
3. 读 `acceptance.md` 的五条采信判据与两项专项判据（形态键转面骨、循环插入接缝），对当前资产复跑一遍，建立自己的基线读数。
4. 与移交方口径冲突时以实测为准，并把新实测写回交接文档「已推翻」段。

## 反馈轮次管理（长周期任务）

- 每轮反馈先复述成带数字的验收条目，确认后再动工。
- 被否决的方案连根移除，禁止置零保留式伪回退；移除动作记入留痕。
- 等回馈期间：离线可判定项排满、观感待裁决项攒批、关闭游戏减少占用。
- 每完成一项写六栏留痕（状态/边界/已完成/下一步/关键决定/偏差）；偏差栏必须含表情数据链的 A2 局部补位清单与未做的实机目视复核（`expression-route.md` §四）。
