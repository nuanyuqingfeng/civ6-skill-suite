# 贴图落色规则矩阵（唯一口径）

贴图侧规则散在 `texture-pass.md`、`leader-pipeline.md` §5、`translucent-pass.md` 三处，2026-11-03 起以本表为准；三处正文若与本表冲突，按本表执行并回头修正文。

## 零、前置闸门：先确认源 alpha 是不是透明度（2026-11-03 新增，最高优先级）

**任何对 `alpha==0` 区做 RGB 补色 / 置零之前，必须先过这一关。** 鸣潮角色基色贴图
（今汐 Skirt / Down / Bangs）的 alpha 常是**材质 / 描线 mask，不是透明度**：实测 Skirt
`alpha==255` 占比 **0.0000**、`mid=0.725`、唯一值 **156**、中位 **103**，是「灰底 + 黑色
块/线」图；黑色区域在 RGB 通道里正是深色轮廓纹样。镂空实际由独立 `Opacity` 槽承载。

| 判据 | 阈值 | 结论 |
|---|---|---|
| `alpha==255` 占比 < 0.005 **且** alpha 唯一值 > 50 | 命中 | **非透明度 mask** → 源 RGB 逐字节保留，**禁止补色 / 置零**；只压平 alpha 到 255 |
| 其余 | — | 按 §二 矩阵继续判 |

工具：`scripts/probes/alpha_semantic_audit.py`（退出码 2 = 非透明度，必须停）。

**反例（2026-11-03 今汐，用户报「今天新流程误伤」）**：把 `alpha==0` 当透明空白区做
`distance_transform_edt` 最近邻补色，抹亮了 top07 右上角 **31%** 的深色线条像素
（源亮度 95.7 → 136.4，+40.7；63.7% 抬升>30、41.2% >60），实机纹路碎裂、出现浅色蚀空斑点。
旧管线无此步，故「今天之前正确」。修法：去掉补色，源 RGB 原样 + alpha 压平 255，
成品与源图逐像素差 **0.00**。判据脚本 `jx_r11_alpha_semantic.py`（工程侧）。

## 一、先问三个问题

1. 这张图是**蒙版/贴花**还是**材质基色**？
2. 如果 opaque 透明度是独立槽，基色 alpha 还参与绘制吗？
3. 这块透明像素**在 UV 足迹里**还是**在足迹外**？

## 二、矩阵

| 贴图角色 | 基色 alpha 参与绘制 | 透明区位置 | 落色策略 | 清 RGB | 依据 |
|---|---|---|---|---|---|
| 蒙版 / 轮廓贴花（**通用**，非鸣潮走这行） | 是（就是靠它切形） | — | 透明区 RGB 置 0，避免彩色毛边；alpha 保留源蒙版，禁止压平；**可见区（alpha>0.9）RGB 原样保留** | 是（仅透明区） | `texture-pass.md` 判据一 |
| **鸣潮**星芒 / 声痕贴花（**仅鸣潮触发**） | 是（就是靠它切形） | — | 三重门全命中才走本行：**RGB 全置 0（含可见区）** + alpha 原样保留。源图 RGB 是 mask 语义不是颜色 | 是（**全图**） | `wuwa-notes.md` §9 |
| 领袖基色（材质**未**绑 `Opacity`） | **否** | 足迹外（padding） | 近邻色即可，只为压 mip | 否 | `leader-pipeline.md` §5.4 P 态 |
| 领袖基色（材质**未**绑 `Opacity`） | **否** | 足迹内（可见） | 按共边投票取面料色；跨色洞禁单色；暗壳上限 +20；判不明就**取上一版已验收贴图的同像素 RGB** | 否 | `leader-pipeline.md` §5.4 V 态 |
| 领袖基色（材质**已**绑 `Opacity`） | 否（切形靠 Opacity 槽） | 足迹内 | 只为防黑边，不得跨足迹边界取色 | 否 | `leader-pipeline.md` §5.4 C 态 |
| 半透薄纱槽（UE 侧 alpha 混合） | 否 | 大面积 | 换不透明主体版本，不靠 alpha | 否 | `leader-pipeline.md` §5.3 |
| 单位材质 | 无 `Opacity` 槽 | — | 轮廓写进几何，贴图不承担透明 | 否 | `case-unit-surface-patch.md` |

**本表只覆盖"RGB 怎么落色"。局部 alpha 打通（只对正面面集的 UV 岛把 α 抬到 255，RGB 逐字节不动）不在本表内**——它改的是 alpha 不是 RGB，口径、不变式与已否决做法见 `translucent-pass.md` §四·五。两张表同时适用时先过 §零 的 alpha 语义闸门。

## 三、三条硬闸门

| 闸门 | 阈值 | 工具 |
|---|---|---|
| 落色与最长邻块色偏差 | ≤25（C 态 ≤40）；仅 `--expect filled` 判失败 | `scripts/probes/hole_fill_audit.py -- --src <png> --dds <dds> --expect filled` |
| 压平前源图透明占比 | 非镂空槽 <0.005 | `scripts/probes/hole_fill_audit.py --stats-only` |
| 可见区（alpha>0.9）新旧逐像素差 | 均值 ≤2、>8 的像素 ≤1% | `scripts/probes/texture_compare.py` |
| **贴花槽 alpha 未被压平** | 源图 alpha=0 占比 >20% 且材质挂 `Opacity` → 判为贴花，成品 alpha=0 占比须与源图相差 ≤1 个百分点 | 逐通道统计（见 §四 第 5 条） |
| **鸣潮星芒可见区已置 0** | 三重门命中时，成品 RGB 最大值 = 0；未命中时此项**不检查**（非鸣潮可见区必须保留原色） | `scripts/probes/wuwa_star_decal_audit.py` |

**行的互斥**：一个槽若同时命中"贴花"与某条"领袖基色"，**贴花行优先**——它要保留 alpha，而领袖基色行要压平 alpha，两者不可同时执行。今汐 `MI_6XingStar` 就是两行都命中、压平赢了的实例，结果黑底整块显形。判定顺序：先看是否挂 `Opacity` 且源图有大面积 alpha=0（>20%），是则按贴花处理。

**贴花行内部再分鸣潮与否**：上面两行贴花的区别只在"可见区 RGB 要不要置 0"。**只有鸣潮星芒/声痕才置 0**，判据是 `wuwa-notes.md` §9.2 的三重门（主题 + mask 语义 + 材质双槽），**三重门全满足才走鸣潮行，否则一律走通用行**——这是"非鸣潮不触发"的硬守卫，别凭槽名像不像就下判断。

## 四、改口径的判据

出现下列任一情况，停下来重判，不要"多处理一点试试"：

- 同一张图上，一部分洞补对、一部分补错 → 可见性判错（边界连通性 vs UV 足迹）；
- 补完以后黑色面料上出现浅色斑 → 跨色洞被单色填充；
- 补完以后浅色面料上出现黑斑 → 用了"置 0"口径；
- **补完以后整图近黑（亮度<30）占比相对上一版明显上升** → 兜底把源图的预乘 0 当成了颜色（源 PNG 预乘 alpha，镂空区 RGB=0 是"无色"不是"黑"）。实测今汐 Down：3.552% → 14.589%，多出的黑块在实机就是边缘毛刺。判据：新旧近黑占比差 >2 个百分点即判失败；
- 补完以后边缘出现彩色毛边 → 该槽其实是蒙版贴花，用错了行；
- **透明区明明该被切掉却整块显形（黑底/色块）** → 该槽是贴花但 alpha 被压平了。源图 alpha=0 区往往不是黑的（今汐六星背景是纯红 (255,0,0)），一旦按"透明区 RGB 置 0"改成黑、再按"领袖基色压平 alpha"清掉蒙版，黑底就会整块画出来。修法：恢复源蒙版（alpha 原样保留），Opacity 槽保留作双保险。
- **黑底切掉了，但图案是彩色的（橙/红/蓝）** → 该槽很可能是鸣潮星芒：源图 RGB 是 mask 编码不是颜色。先跑三重门（`wuwa-notes.md` §9.2），**命中**才把可见区 RGB 也置 0；**没命中就是普通贴花，绝不能置 0**，否则图案整块变黑。判据：`scripts/probes/wuwa_star_decal_audit.py`。
