# 闭眼与眼睑（blink / eyelid）

> 眨眼是领袖脸部最容易"看起来做了、实际没做"的动作：曲线有、骨骼动、但屏幕上要么不眨，要么闭一半。本文给通道选择、事件分类与验收口径。

## 一、三层驱动，先定谁说话

眼睑同时被三条通路驱动，必须明确优先级，否则同一条通道被叠加两次：

| 通路 | 载体 | 特点 | 适用 |
|---|---|---|---|
| 曲线层 | 官方 `E_Close` 逐帧权重 → 形态键拟合层 | 幅度小、被分摊到多根骨 | **不适合**做完整闭眼（见第二节） |
| 姿态层 | blink 通道 → `LidUp`/`LidLo` 平移 | 幅度可控、行程由眼球跨度定 | **完整闭眼 / 长闭眼** |
| 形态键层 | `E_Smile_*` 等拟合到面骨 | 与表情一起走 | 眯眼笑这类表情性闭合 |

原则：**同一帧同一个眼睑，只允许一条通路主导**。混合时先算姿态层的目标位移，再让形态键层做残差，最后统一限幅。

## 二、`E_Close` 不能直接走拟合层

这是踩过的坑，写死在判据里：

- `E_Close` 的形变 delta 很小（约 1 cm 量级），且经 Kabsch 拟合后被**分摊到多根面骨**；
- 结果是 `LidUp` 只下压约 **0.4 倍**行程（半闭），`LidLo` 甚至被顶向**反方向**；
- 画面上表现为"眼睛眯了一下但没闭"，或"闭眼时下眼睑往外翻"。

正确做法：把 `E_Close` 的**逐帧权重**注入姿态层的 blink 通道，用由眼球竖直跨度算出的完整行程执行：

```
BLINK_DOWN_CM = 0.75 * eye_v          # eye_v = 眼球网格的竖直跨度
drop          = BLINK_DOWN_CM * blink
lid_up        = -drop
lid_lo        = +drop * LOWER_LID_RATIO   # 0.4 左右
```

实测：某角色去拟合层后 `LidUp` 行程 0.66 cm（应有 1.55），下睑被顶到 1.43 cm 且方向相反。

## 三、事件分类：短脉冲 vs 长闭眼

`E_Close` 曲线里混着两类事件，处理方式不同：

| 类型 | 帧长 | 处理 |
|---|---|---|
| 短眨眼 | 4–15 帧 | **交回项目既有的眨眼频率**（`blink_plan` 之类），不要用官方脉冲去改频率 |
| 长闭眼 / 表情性闭合 | > 20 帧 | **按官方逐帧权重忠实复刻**，这是演出的一部分（入场、低头、哀悼） |

分离方法：对 `E_Close` 逐帧阈值化（> 0.02），统计连续段长度，按阈值分类。分类结果要落盘，便于复现。

判定补充（「交回人工」的 A2 边界——`expression-route.md` §三）：

- 整段 `E_Close` 峰值 < 0.05 的片段（官方根本没眨眼曲线）→ 整体交回人工眨眼计划，不要强行接管；
- `f > source` 的合成保持段，官方曲线已停更，若连眨眼一起冻结会"瞪眼"数秒 → 交回人工。
- 以上两条与「短脉冲交回 blink_plan」同属 **A2 局部补位**（御三家已验证链路），照常执行但必须在报告记录；
- **整条官方曲线来源缺失 / 白名单全空不属于 A2**——先补导（`unpack-expression-curves.md`）再复核，仍无命中必须走 `expression-route.md` §三询问协议，未获用户明确点名授权 = ABSTAIN 不做，禁止静默降级。

## 四、合成后必须限幅

眯眼笑（形态键把 `LidLo` 抬起）与眨眼（姿态层继续抬）叠加会穿进脸面。限幅要放在**两路都算完之后**，只裁超出部分，不改任何一路的曲线：

```
LID_CLAMP_UP = BLINK_DOWN_CM * 1.18
LID_CLAMP_LO = BLINK_DOWN_CM * LOWER_LID_RATIO * 1.8
# 相对 rest 的总位移超过上限 → 按比例缩回，方向不变
```

顺序固定：`pose_face()` → 形态键叠加 → **限幅**。

实测：某段 167 帧里，眯眼笑让下睑抬了 1.43 cm，叠加眨眼后到 1.98 cm（完整闭眼只需 0.62），限幅后回落到 1.10。

## 五、下眼睑的特殊陷阱

三条都实测过，写下来避免重走：

1. **行程系数**：下睑只走上睑的 40% 左右。给满行程会让下睑顶到上睑，闭眼时像"翻白眼"。
2. **轴向不可假设**：眼睑骨的本地轴随骨骼朝向变化。上睑骨朝上、下睑骨朝下，同一个 `_shift_local` 作用在两者上，世界方向可能一个是竖直、一个是**深度**。判据是逐轴看位移，不是看总长度。
3. **导出会压缩**：从 Blender 世界坐标看到的位移，到 fgx 的局部平移可能换轴并缩小（实测有 1/6.7 的情况）。**验收必须看最终 fgx 的局部值**，不能拿 Blender 里的世界值当结论。

## 六、验收口径

| 项 | 正确取法 | 错误取法 |
|---|---|---|
| 幅度 | fgx 里该骨 **pz/px 的绝对 min–max** | 相对第 0 帧的偏差（第 0 帧可能恰在峰值附近） |
| 事件 | 逐帧阈值化的连续段，与计划表逐条比对 | 只看最大值出现的那一帧 |
| 采样 | 采样数 = 片段真实总帧数 | 固定 120/32 帧（会漏掉 4 帧的短眨眼） |
| 可见性 | 几何主导顶点数 ≥ 判据 | 只看动画幅度 |

**"闭合幅度够"与"画面能看见"是两件事**，后者归 `face-skin-gate.md`。

## 七、红旗清单

- 实机不眨，但动画里 `LidUp` 幅度正常 → 先查几何蒙皮，不要查曲线；
- 闭眼只闭一半 → `E_Close` 走了拟合层，改走 blink 通道；
- 闭眼时下眼睑外翻 → `LidLo` 方向取反，检查骨的本地轴；
- 眯眼笑时眼周穿模 → 缺合成后限幅；
- 眨眼频率与项目既有节奏不一致 → 官方短脉冲抢了控制权，按第三节交回人工；
- 某一段一直"瞪眼" → `f > source` 的冻结段没有交回人工；
- 下睑保底/限幅没生效或误触发 → 运行时层用 `scripts/face_expr_runtime.py`（`ensure_lid_close` 在 `pose_face`+`morph_fit.pose` 之后、`clamp_lids` 之前；参数化常量与御三家逐值一致）。
