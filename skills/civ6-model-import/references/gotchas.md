## 缩写规范（硬性）

新增资产名、骨骼名、前缀、脚本内常量时，缩写按下面顺序取值，禁止沿用模板工程的缩写。

1. 优先用该工程自己的内部缩写。素材导出侧本来就有编号或模块名时直接沿用，模型实例名、骨架名、动画轨道组名都跟着同一串编号走。鸣潮素材的编号形如 `R2T1<角色>Md<编号>`，实例见 `wuwa-notes.md` 第二节 <!-- WUWA -->
2. 工程内部没有缩写时，用「工程缩写 + 领袖缩写」，例如 `HTR_Mint`（Hethereau 的 `HTR` 与薄荷的 `Mint`），面骨前缀写 `MINT_Jaw`、`MINT_Brow_L`。
3. 模板工程的缩写只能留在模板工程里。薄荷工程沿用今汐模板时把面骨写成 `JX_*`，是缩写混用的实例：现在统一改为 `MINT_*`，脚本里一并替换，重烘后由 `.geo` 与 `.ast` 自动带上新名字。

判定口径：`grep -rn '<模板缩写>_' 工程目录` 在模型与动画资产里应为 0 命中；脚本里出现模板缩写只允许出现在「引用模板工程文件路径」这类与交付无关的位置。

改前缀要连带三处，漏一处就报 `KeyError` 或退化成静止：

1. 片段名。内部片段名直接用「领袖代号 + 后缀」，输出侧的重命名映射退化成同名对（`BZH_IDLE:BZH_IDLE`），装配脚本不再做字符串替换。
2. 骨骼名。面骨在建模脚本里按「代号 + 后缀」生成，权重字典、姿态字典、形态键权重扫描全部走同一个前缀常量，避免出现字面量残留。
3. 通道基准表 `workspace/gen/reports/anim_channel_map_<角色>.tsv`。面骨那 18 行带的是旧前缀，脚本按代号查表时直接 `KeyError: 'BZH_Jaw'`；改名后同步替换这 18 行的前缀再重烘。

## 单位（Unit）资产实战（2026-10-31 Rover 工程）

单位类资产 `m_ClassName=Unit`，与领袖链共用 cn6/FBX/XLP/cook，差别集中在 artdef 元素名与「单位包只装 AST、曲线落 SHARED_DATA」。以下每条都在实机复现过，按现象查。

| 现象 | 根因 | 处置与判据 |
|------|------|------------|
| 模型完全不显示，包已加载、cook 无报错 | 源 DDS 是 DXT5，`.tex` 声明 `PF_R8G8B8A8_UNORM`，cooker 取不到像素，产物全零 alpha | 源图转未压缩 RGBA8 后重 cook。判据：`SHARED_DATA/TEXTURE_*` 的 distinct 字节数远大于 1（本次 250–256），修前为 1。本机 texconv 为 DirectXTex 2026.5.8.1，`-f RGBA8` 被拒，用 `-f R8G8B8A8_UNORM` |
| 模型巨大、悬空、肢体散架，去掉动画就正常 | 片段坐标系与模型静止姿态不同源（源骨架 `Rz(90°)` 未消；或把「帧 0 相对增量」当骨骼局部旋转） | 按 `anim-rest-anchor.md` 三条锚点重解通道；先做 `IDLE_A` 过闸再批量 |
| 一条动画坏掉，整具模型消失 | cooker 把 AST 整体替换成 error asset：`Error condition propagated from ANIM '<clip>' to ASSET '<ast>'` 后紧跟 `Replacing asset: (<ast>) ... with error asset` | 搜 `cooker.log` 这两句；包体从 989184 掉到 91136 就是这种 | 
| 两个 mod 同时启用时模型行为无法解释 | 两个 mod 各带同名 `ArtDefs/Units.artdef` 与同名元素，引擎对同一路径只留一份，元素归属日志不记 | 对照实验必须单 mod；`Mods` 下同类 mod 只留一个，其余整目录移出 |
| 拿 `units/*.blp` 的哈希判断动画是否更新 | 单位包只装 AST，曲线落在 `SHARED_DATA/ANIMATION_*`；包哈希对曲线字节不敏感 | 动画是否刷新看 `SHARED_DATA` 的 `ANIMATION_` 条目数与字节数，包哈希只用于证明结构未变 |

| 想给动画清零位移却无接口 | `IGrannyCurve` 只暴露 `Sample`、`KnotCount` 等读接口，没有写曲线的 setter | 曲线只能由 FBX 侧重烘；不要在这条路上花时间 |

## 贴图侧实战（2026-11 今汐定稿）

贴图整包换源、掩膜替换、局部调色三类动作的实际故障。流程与判据见 `texture-pass.md`。

| 现象 | 根因 | 处置与判据 |
|------|------|------------|
| 头发与浅色外衣整块消失，cook 退出码 0、九类告警全 0 | 材质 `Opacity` 引用的掩膜 DDS 头字段被工具产物覆盖：`pixelformat.dwFlags`（偏移 80）由 `0x40` 变 `0x20000`、`caps`（偏移 108）由 `0x401007` 变 `0x401008` | 只改回这两个字段，负载逐字节不动（87,509 字节案例），头发立即恢复。判据：`dds_tex_verify.py` 打印的两字段与工程既有掩膜一致 |
| 头发发灰、发丝层次全无，像是被涂平 | 基色取自明度图 `_LD` 并乘系数放大，得到最小 132、均值 185、暗像素 0% 的过曝图 | 基色只取 `_D` 族；重出后读数应落在最小 80～90、均值 160～190、暗像素 5%～15% |
| 局部提亮或刷色后，双马尾发尾、浅色缎带、图集空白区一起被改 | 用颜色阈值或形态学开运算定位，圈不到“哪一块是哪里” | 先按主导骨骼导出 UV 三角栅格化成掩膜，再与颜色判据相交；掩膜预览出现发尾条带或空白区即定位错误 |
| 垂发中段一直留灰，反复纳入骨骼仍不干净 | `Hair002/006`、`Hair003/007` 被当成双马尾而未纳入，实为两侧垂发一二段 | 按骨骼分组表纳入；今汐定稿共十二段骨骼、7,726 个三角 |
| 阈值替换后出现硬边色块 | 阈值边界处没有过渡，或整片同值替换 | 保留层次改用平滑曲线 `L′ = 208 + 0.22 × (L − 208)`，再按 `基色 × (L′/205)` 上色；纯灰块才用阈值替换加羽化 |
| 改了 DDS 尺寸后 cook 回显 `falling back to uncompressed`，或 BLP 体积异常 | DDS 头尺寸 / 像素格式与 `.tex` 声明不一致，或同槽内尺寸混杂（**与是否 2048 无关**） | 按 `texture-pass.md` §五 核对「源图 → DDS 头 W/H/mips → .tex W/H/mips」三处一致；2048² / 4096² 均合法，不得因回退提示就退回 1024² |
| 贴图改完直接 cook，靠进游戏判断 | 每轮付一次完整 cook 与部署 | 先跑 `open_model.py` 预览，末行 `OPEN_MODEL_OK` 才 cook |
| Blender 4.5 无头导入 cn6 报 `create_normals_split` 缺失 | 用的是默认脚本目录下的插件副本 | 设 `BLENDER_USER_RESOURCES=E:\SoftWares\blender45\userres` 后用 `open_model.py` 或自有脚本 |
| 黑色布料上出现肤色斑，看着像布料缺损 | 补色把最近邻的皮肤色灌进黑布：洞横跨两块面料，最近邻恰好取到肤色 | 按 `leader-pipeline.md` §5.4 三态重判；跨色洞禁用单色，兜底取上一版已验收贴图的同像素 RGB（**不是**源图 RGB）。判据 `scripts/probes/hole_fill_audit.py` 偏差 ≤25 |
| 贴图边缘出现毛刺、锯齿，黑色区域比旧版大一圈 | 兜底"保留源图 RGB"写成了纯黑：源 PNG 预乘 alpha，镂空区 RGB=0 意为"无色"非"黑" | 兜底改取上一版已验收贴图 RGB；验收加"新旧近黑（亮度<30）占比差 ≤2 个百分点"。今汐 Down 实测 3.552% → 14.589% |
| 贴花（星芒/声痕/轮廓）整块显形：该透明的地方露出黑底或色块 | 该槽同时命中"贴花置 0"与"领袖基色压平 alpha"两行规则，压平把蒙版清掉了。源图 alpha=0 区常填纯色（今汐六星填纯红），置 0 后变黑、蒙版再被压平，黑底就整块画出 | 贴花行优先：**保留源 alpha 蒙版**，透明区 RGB 仍置 0，Opacity 槽作双保险。判据：成品 alpha=0 占比须与源图相差 ≤1 个百分点（今汐六星 94.54%）。判定顺序见 `texture-rules-matrix.md` §三 |
| 上一条修好后，黑底没了但**图案是彩色的**（橙/红/蓝） | 只恢复了蒙版，可见区 RGB 还留着源图的 mask 编码色（今汐六星星芒是 (255,130,39) 橙黄），`Leader_Matte` 直出就成彩色光效 | 跑三重门 `scripts/probes/wuwa_star_decal_audit.py`：**命中（仅鸣潮）**才把可见区 RGB 也置 0；**未命中严禁置 0**，否则普通贴花的图案会整块变黑。见 `wuwa-notes.md` §9 |
| 同一槽里一半洞补对、一半补错 | 用"是否连到图像边界"判可见性；岛密铺时岛间缝也不连边界，被误判成岛内可见洞 | 可见性一律用 UV 足迹判（`dump_hair_uv.py` 栅格），不用边界连通性。今汐 Down 实测误判率 41.6% |
| **深色轮廓/纹样碎裂、出现浅色"蚀空"斑点，且是换了新流程才出现、之前正确** | 把源 alpha 通道误当透明度，对 `alpha==0` 区做了最近邻补色 / 置零。鸣潮基色贴图 alpha 常是材质 mask（Skirt： `alpha==255` 占比 0.0000、唯一值 156、中位 103），黑色区域在 RGB 里正是深色描线 | **先跑 `scripts/probes/alpha_semantic_audit.py`**（退出码 2 = 非透明度）：源 RGB 逐字节保留，只压平 alpha，**禁止任何补色**。今汐 Skirt 实测补色抹亮 31% 线条像素 +40.7 灰度（63.7% 抬升>30），去掉后成品与源图逐像素差 0.00。见 `texture-rules-matrix.md` §零 |

| 编号 | 症状 | 处置 |
|---|---|---|
| 87 | 动画逐骨差分全 PASS，实机表情/眨眼完全无变化 | 几何 `palette` 里没有面骨（重构几何时常被整包丢弃）。跑 `scripts/face_skin_gate.py` G1，或 `NexusMeshTable` 看 `FAM(面骨) verts`。判据与补权重方法见 `face-skin-gate.md` |
| 88 | 眨眼只闭一半，下眼睑还往外翻 | `E_Close` 走了形态键拟合层（delta 被分摊到多骨）。改注入 blink 姿态通道，用眼球跨度算完整行程；下睑按上睑 40% 取。见 `blink-and-eyelids.md` 第二节 |
| 89 | 眯眼笑时眼周穿模，下睑顶到上睑外 | 形态键层与 blink 通道各抬一次，叠加超物理上限。在**两路都算完之后**按 `BLINK_DOWN_CM` 的比例限幅，只裁超出部分。见 `blink-and-eyelids.md` 第四节 |
| 90 | 读数 exe 连续崩溃，换资产也一样 | 输出路径过长触发 native 缓冲区越界，不是"偶发"、不是资产损坏。输出一律落 `%TEMP%` 短路径；能稳定复现的就不是随机故障 |
| 91 | 短眨眼在验收里"没有发生过" | 采样数固定 120/32，漏掉 4 帧的脉冲。采样数必须等于片段真实总帧数；判读看连续段，不看最大值所在帧 |
| 92 | 改了源文件，cook 成功，但产物字节一点没变，误判成"没进包" | 拿"两轮都没有变化的产物"互比，基准就错了。必须与**变更前备份**比；另注意 Cooker 按内容判依赖，源没变会复用缓存 |
| 93 | 按要求"去掉某段动画"，实机却还在播 | 把"不引用"做成了"降级为 IDLE"。两者语义不同：不引用=四处容器都不出现，降级=槽位保留改播待机。见 `ast-anim-binding.md` 第二节 |
| 94 | 治标补丁引入新问题，之后一直跟这个补丁死磕，最后证明它根本不需要 | 补丁与治本混装在一个 `apply()` 里，无法单点关闭，于是删不掉。规则：补丁必须默认关闭、可单点开关、自报改动量、写退出条件；用户说"不需要"时**立即做 A/B 而不是解释**。见 `patch-lifecycle.md` |
| 95 | 关掉某个补丁后行为无法解释（比开着还怪） | 说明它已被其它逻辑隐式依赖，或它掩盖的病灶仍存在。此时不许"加回来就算了"，要么查清依赖链，要么隔离并写复审日期 |
| 96 | 两个工具读同一资产，形状/数值不同 | 工具挂载的数据源版本不同（补丁包、密钥、缓存）。先查版本再查处理；"游戏资产本来就这样"是最容易错的结论。见 `misattribution.md` 第二节 |
