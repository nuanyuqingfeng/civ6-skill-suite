# 补丁生命周期（治标脚本的准入、冻结与删除）

> 一句话：**补丁必须能被单独关掉；关不掉的不叫补丁，叫负债。**

## 一、典型失败的结构

一个"治标"脚本变成拆不掉的房子，通常不是态度问题，是形态问题。实例抽象：

```python
def apply(mesh, char):
    shift_bangs(...)      # 治标：位置微调
    face_front(...)       # 必要：补材质槽，防转换器越界崩溃
    shift_hair(...)       # 治标：位置微调
    for _ in range(3):
        push_cloth(...)   # 治标：挡住穿模
    overlap_counts(...)   # 诊断
```

三个缺陷叠加：

1. **治本与治标混装**：必需的 `face_front` 和治标的 `push_cloth` 在同一函数里，删谁都得动整包；
2. **无条件调用**：模型链和**动画链**都 import 它（动画烘焙跑模型修复，本身就不该发生）；
3. **开关粒度太粗**：只有全局 `NO_MESHFIX`，做不了"只关 push_cloth"的对照。

结果：删了怕崩，留着持续污染，只能继续叠补丁——**这是结构的必然，不是判断力问题**。

## 二、准入四问（提出前必须能答）

| # | 问题 | 答不出 |
|---|---|---|
| 1 | 病灶定位到哪一行/哪几个顶点？证据是什么？ | 不许写 |
| 2 | 它绕过什么？被绕过的那层会不会本来就是错的？ | 大概率在掩盖真 bug |
| 3 | 能单点关掉吗（一行参数/env）？ | 不许合入 |
| 4 | 什么现象消失后它必须删？ | 它会永久留下 |

附加：**单因单补丁**。一个补丁只允许一个理由，混装必须当场拆成独立函数。

## 三、五个"立刻停止"信号

1. 同一症状要上**第 2 个补丁**；
2. 补丁需要**另一个补丁**来抵消副作用；
3. **关掉它之后行为无法解释**（说明已有隐藏依赖）；
4. **用户说"这个不需要"→ 立即做 A/B，不许辩**；
5. 你说不清它修的是哪一行。

触发任一条：停止写补丁，回到"病灶定位是否从一开始就错了"。

第 4 条单独强调：正确回应不是解释它为什么有用，而是**把 A/B 数据摆出来**。争辩浪费的是用户的时间。

## 四、四类处置

| 处置 | 适用 | 动作 |
|---|---|---|
| **删除** | 关掉后结果不变或更好；病灶已在别处修好 | 直接删，跑全套闸门确认无回归 |
| **转正** | 关掉后确实变差，且能说清修的是什么 | 从"补丁"改名"必要步骤"，写清原理与判据，进入正式流程 |
| **隔离** | 删了不确定，当前也不需要 | 移到 `quarantine/`，移出构建链，标注复审日期 |
| **降级为诊断** | 只统计/只观察，不改数据 | 从 `apply()` 移除，改为独立探针 |

判定只看一件事：**关掉之后产物变不变**。不看代码觉得它有用。

## 五、A/B 三步（关—跑—比）

1. **关**：单点关闭该补丁（不是整包关闭）；
2. **跑**：同一套闸门 + 同一段实机对照；
3. **比**：

| 结果 | 结论 |
|---|---|
| 不变或更好 | 删除 |
| 变差且可量化 | 转正，写清修什么 |
| 无法判断 | 隔离，限期复审 |

## 六、台账 `PATCHES.md`

每个临时补丁一行，缺任一列不许合入：

```
名字 | 加它的原因 | 绕过了什么 | 开关 | 退出条件 | 状态 | 复审日期
```

状态四值：`active` / `frozen`（禁止再叠）/ `quarantined` / `removed`。

**frozen 的意义**：当一个补丁已经被证明是误判的产物但尚未删除时，先冻结——禁止在它上面再加任何东西，防止债务滚雪球。

## 七、脚本形态约束

治标脚本必须满足三条，缺一不许合入：

1. **默认关闭**，显式参数/env 打开；
2. **自报改动量**：`<NAME>_APPLIED <项> <n>`，跑完日志里能看到它动了多少；
3. **带退出条件注释**：文件头写清"什么现象消失后应删除本文件"。

模板：`scripts/_patch_template.py`。

## 八、删除后的回归

删除不是终点，必须确认没有回归：

- 跑同一套闸门（几何蒙皮、动画轨迹、cook 四类告警、部署指纹）；
- 检查产物体积/顶点数/骨骼数是否落在预期区间；
- 若删后变差 → 说明它确实有用，**转正**而不是"悄悄加回来"。

## 九、红线

- 不许在 `apply()` 这类总入口里混装治标与治本；
- 不许让动画链调用模型修复（链路职责分离）；
- 不许保留"说不清修什么"的补丁；
- 不许用"先留着，以后再说"作为保留理由——要么转正，要么隔离并写日期。
