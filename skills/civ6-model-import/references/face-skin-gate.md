# 几何蒙皮闸门（面部通道能不能被看见）

> 本文解决的是**离线全绿、实机却毫无表情**这类问题。它在验收链里的位置比动画曲线更靠前——动画再对，几何里没有面骨权重，屏幕上就是不动。

## 一、为什么必须有这一层

引擎播放的是**骨骼动画**，骨骼动不等于画面动。顶点要跟着动，必须满足两件事同时成立：

1. 动画 fgx 里有这根骨的轨道（`acceptance.md` §形态键转面骨 管的是这一层）；
2. 几何 fgx 的 mesh palette 里**有这根骨，且顶点权重非零**。

第 2 条藏在几何文件里，任何只看动画的验收脚本都读不到。**验收工具与被测对象同源时，盲区不会自曝。**

典型误判链：动画逐骨差分全 PASS → 判断"表情已修好" → 实机不动 → 怀疑曲线权重 → 怀疑形态键 → 怀疑 blink 通道……真正的原因在几何，而它从来没被检查过一次。

## 二、三层各管什么

| 层 | 载体 | 能证明什么 | 不能证明什么 |
|---|---|---|---|
| 骨骼声明 | `.geo` 的 `<m_Bones>` / `<m_nBoundBoneCount>` | 骨架里有这根骨 | 有没有顶点绑它 |
| 真实绑定 | 几何 `.fgx` 的 mesh `palette` | 这根骨被 mesh 引用 | 权重多大、影响几个顶点 |
| 影响面 | `NexusMeshTable` 的 `FAM Other(<骨>) verts=N` | 主导骨是它的顶点数 | 弱权重顶点（非零但非 argmax） |

**只看第 1 层会得出完全错误的结论。** 三者必须一起看。

## 三、三项必查

```bash
# 1) 骨骼声明（文本，最快）
grep -c '<Element text="<CODE>_' <Geo>.geo          # 期望 18 根面骨全部出现
grep -n 'm_nBoundBoneCount' <Geo>.geo

# 2) 真实绑定 + 影响面（二进制，需要读数工具）
#    输出务必写短路径，长路径会触发 native 崩溃，见 gotchas
<NexusMeshTable.exe> <Geo>.fgx > C:/Temp/mesh.txt
grep -o 'palette=\[[^]]*\]' C:/Temp/mesh.txt        # 面骨名是否在 palette 内
grep 'FAM .*(<CODE>_Lid' C:/Temp/mesh.txt           # LidUp / LidLo 主导顶点数
```

打包闸门 `scripts/face_skin_gate.py`（G1+G2+G3 一键）的调用要点：

- 几何/装配定位按 `--code-map '{"YYY":"Yangyang","DJ":"DanJin"}'` 与 `--geo-pattern` 通配，不再硬编码 `LEAD_YSJ_*` 与角色代号表（代号 ≠ 文件名的工程必给 code-map，否则 G3 报 GEO_MISSING）；
- dump 读数成功判据 = **退出码 0 且产物完整**（原生崩溃会留下截断 TSV，只查大小会把残件当成功），高频采样崩溃自动降采样 120/96/64/48/32；
- 输出统一落 `C:\Temp\civ6_gate`（%TEMP% 路径偏长时 dump 会截断输出，2026-11-06 实证）；
- `--inject` 五项：`no-face-skin` / `weak-blink` / `lower-lid-static` / `no-curve` / `unauthorized-fallback`，配合 `scripts/gate_selftest.py`（默认全五项）验证区分力。

### 判据表

| 项 | 阈值 | 依据 |
|---|---|---|
| 面骨在 palette 内 | 17/18 根（`LipLo` 通常 0 权重，不算缺） | 面部形变只需要 17 根 |
| `LidUp_L/R` 主导顶点 | ≥ 150 | 低于此值闭眼在画面上的面积不足 |
| `LidLo_L/R` 主导顶点 | ≥ 30 | 低于 30 时下眼睑的位移看不出来 |
| `Eye_L/R` 主导顶点 | ≥ 90 | 瞳孔/注视通道的载体 |
| 其余面骨 | > 0 | 表情层能落地 |

任一不达标即 **FAIL**，不要进入动画侧的讨论。

## 四、两种统计口径不要混

| 口径 | 含义 | 用途 |
|---|---|---|
| `NexusMeshTable` 的 `FAM(骨) verts=N` | **主导骨**是它的顶点数（argmax） | 判断"这块区域的形变归谁"，反映视觉可辨识度 |
| cn6 顶点行里的 bone id / weight | **任意非零**权重即计入 | 判断"权重是否真的写进去了"，反映通道连通性 |

实例：同一份资产在 cn6 口径下 `LidLo` 有 158 个非零顶点，而在主导骨口径下只有 32。两个数都对，回答的是不同问题。

**排查时的顺序**：先用 cn6 口径确认"权重写进去了"，再用主导骨口径确认"写入的位置能看见"。前者失败是写权重的问题，后者失败是**权重分布**的问题（需要扩大掩膜，不是重导）。

## 五、跨版本补权重（cn6 文本就地改）

当新几何把面骨整包丢了（"仅几何+骨架"式重导是最常见原因），不必重跑整条模型链。cn6 是**文本格式**，可以就地补：

1. 找一份**同网格、带面骨权重**的历史 cn6（同一角色的早期导出版本即可）。校验三个不变量：骨骼列表（含顺序）、顶点数、包围盒。顶点坐标允许有重导出级误差（同网格两次导出通常 < 0.05 cm）。
2. 逐顶点按**索引**迁移（顶点数一致时索引即对应；不一致时用最近邻并限制距离）。
3. 合并规则：

```
add   = 旧版中 bone_id ∈ 面骨集合 且 weight > 0 的项
keep  = 1 - min(sum(add), 1.0)                 # 缩放新版本已有权重
pairs = [ (b, w*keep) for 新版本非面骨项 ] + add
取权重最大的 8 组 → 归一化 → 量化到 0-255
```

4. 自检（缺一即回退）：权重和 ≈ 255、无零权重顶点、≤ 8 组影响、骨骼列表与材质槽与基底完全一致、顶点数与三角数不变。
5. 走 `NexusBatch` 重转 fgx/geo/wig，再用本文第三节复检。

**不要整行覆盖**：新版本可能改过材质槽、法线、刘海翻转，整行覆盖会把这些一起冲掉。

### 面骨定位按后缀，不按前缀

面骨命名是 `<代号>_<后缀>`（`LidUp_L`、`Cheek_R`…）。跨版本迁移时按**后缀**匹配，前缀用当前工程的代号常量生成。历史资产可能是别的代号（甚至上游角色的 `JX_*`），按前缀硬编码会得到"一根都没匹配上"的静默失败。

## 六、红旗清单

出现以下任一情况，先查本文，不要先动动画：

- 动画逐骨差分全 PASS，但实机表情/眨眼完全无变化；
- 某根面骨在动画里幅度正常，画面上的对应区域纹丝不动；
- 只有上半脸能动、下半脸不动（或反之）；
- 某个角色全部表情失效，另外两个角色正常（同一套动画数据）；
- 几何是"仅几何+骨架"重新导入的（这是最高危信号——它通常明确写着不复刻权重）。
