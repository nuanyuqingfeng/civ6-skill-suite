# 形态键曲线 → 逐帧权重表 → 烘焙

> `acceptance.md` §形态键转面骨 讲的是"顶点 delta 怎么拟合成骨增量"；本文讲**另一条数据源**：动画资产里逐帧记录的形态键权重曲线，以及怎么把它变成每段动画的逐帧权重表。

## 一、两套数据源，别混用

| 来源 | 内容 | 用途 |
|---|---|---|
| PSK/网格 `MRPHINFO`/`MRPHDATA` | 每个形态键的**顶点位移 delta** | 建立"形态键 → 面骨刚体增量"的拟合表（一次性） |
| 动画 `.ueanim` 的 curve 集 | 每段动画里每个形态键的**逐帧权重** | 决定"哪一帧该用多大权重"（逐段） |

前者解决"怎么动"，后者解决"何时动、动多少"。只做前者 = 表情永远只有一个固定强度；只做后者 = 没有通道可以驱动。

## 二、曲线文件结构

典型 JSON：

```json
{
  "numFrames": 221,
  "fps": 30.1,
  "curves": {
    "E_Close": { "times": [...], "values": [...] }
  }
}
```

要点：

- `values` 与 `times` 等长，`times` 等间隔（实测 fps 在 **30.10–30.86** 之间浮动，**不是严格 30**）；
- 值域通常 `[0,1]`，是权重不是位移；出现 >1 或负值说明拿错了轨道；
- `numFrames` 是**帧数**，可用的帧区间上界是 `numFrames - 1`。

## 三、白名单与排除

**纳入**（按用途分三组，便于按需开关；与御三家已验证链逐字对齐）：

| 组 | 前缀/名字 | 用途 |
|---|---|---|
| 表情 | `B_` / `E_` / `M_` / `C_` | 眉、眼、嘴、脸型 |
| 瞳孔 | `Pupil_*` | 瞳孔位移/缩放 |
| 口型 | `Aa` + 单字母元音 `A/E/I/O/U`、`P_M_*` | 源动画自带的嘴形（**不是语音适配**）。**Aa 不可省**：缺它会整列丢失元音键（2026-11-06 P1 回归实证，仅 Yangyang Defeat 受影响） |

**排除**（每一类都有踩坑记录）：

| 名字 | 实际是什么 | 为什么排除 |
|---|---|---|
| `morpher_*` | 值域 1.4–100 的参数曲线 | 不是 0–1 权重 |
| `Eye01…Eye10` / `Pupil01…` | 眼球**材质参数** | 形态键表里没有对应项 |
| `UI_Eyes_Control` | 恒为 1 的开关 | 无信息 |
| IK / 开关类 | 运行时控制 | 与形变无关 |

**判定方法不是猜前缀，而是交叉核对**：把曲线名与形态键清单求交集，命中且拟合表里 `bones > 0` 的才可用。

## 四、帧对齐必须实测

不要用 fps 反算，直接在 Blender 里读每条源动画的 `frame_range`：

```python
act = import_clip(path)
lo, hi = act.frame_range          # 实测恒为 (0, numFrames-1)
L = hi - lo
```

NLA 拼接时 **strip 长度 = L**，第 i 帧对应曲线 `values[i]`。这一步错了，整段表情会整体漂移。

## 五、拼接与填充规则（2026-11-06 口径修正，勿回退）

一段目标动画由多段源动画拼成（`segments` + `repeat` + `total`）：

1. 按 `segments` 顺序铺 strip，`repeat=n` 表示重复 n 次；**一条 strip 占 L 帧，区间半开 `[start, start+L)`——段边界帧属于下一段的第 0 帧**，与身体动画 NLA 铺帧一致。闭区间会让边界帧重复计入前段，多段表整体漂移一格（P1 回归实证：12/18 表 DIFF 的主因）；
2. 累加长度超过 `total` 时**截断**；
3. 累加长度不足 `total` 时，在 `source` 之后**冻结**——冻结值是 **NLA HOLD 的动作末帧采样 `v[-1]`**（不是 `v[L-1]`），与身体动画的保持帧一致；不要循环、不要补零。`targets` 可显式给 `source`（身体动画保持帧，御三家 TARGETS 同源），缺省取各段 L 之和；
4. 每段只取白名单内的曲线，段内越界的索引钳到末帧。

冻结段是一个容易被忽略的语义：它意味着"官方数据到此为止"，后续应由人工层接管（见 `blink-and-eyelids.md` 第四节）。`scripts/morph_curves.py --require-source`（默认开）在全部片段都无白名单命中时以 `CURVE_SOURCE_EMPTY` 非零退出——**静默产出空表不是合法结局**，回 `expression-route.md` 走补导或询问协议。

## 六、与人工层的融合

两条线（官方曲线 / 人工预置）同时存在时，用**互补混合**而不是取大或相加：

```
w = 1 - (1 - w_curve) * (1 - w_manual * GAIN)
```

- `GAIN` 是人工层的降权系数（0.4–0.6 常见），用来避免人工预置压过官方微表情；
- 结果天然 ≤ 1，不会溢出；
- 某键只在一边出现时，等价于直接采用该边。

若某段本来就没有人工预置（例如待机），混合后退化为纯官方曲线，无需额外白名单。

## 七、校验：双实现交叉

权重表生成器必须有**第二条独立实现**做交叉核对：

- 一条按"段 → 帧 → 索引"正向生成；
- 一条按"目标帧 → 反推源帧"逐点采样；
- 两者逐帧逐键比较，要求 `MAE = 0`、`MAX = 0`。

单实现自测只能证明"没崩"，不能证明"对"。这条和 `misattribution.md` 的双通道原则是同一个道理。

附加自检：

| 项 | 期望 |
|---|---|
| 每张表的 `active_frames` | 与源曲线的非零帧数量一致 |
| 每张表的峰值 | 与源曲线峰值一致 |
| 键数 | 只含白名单内且拟合表 `bones > 0` 的键 |
| 冻结段 | 与动作末帧（NLA HOLD，`v[-1]`）逐键相等 |
| 与已部署链等价 | 对已验证工程的同源表逐帧逐键 MAE=0（2026-11-06 御三家 18/18） |

## 八、红旗清单

- 表情整体偏移几帧 → 帧对齐用了 fps 反算而不是实测 `frame_range`；
- 循环动画接缝处表情突跳 → 末段没做循环收口（末 N 帧向首帧收敛）；
- 某键权重恒为 1 → 拿成了开关类曲线；
- 表情强度整体变弱 → 人工层 `GAIN` 过高，或官方曲线被人工层覆盖；
- 换角色后表全空 → 白名单前缀与当前代号不匹配（按后缀匹配，见 `face-skin-gate.md` 第五节）。
