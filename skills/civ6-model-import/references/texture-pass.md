# 贴图侧流程与判据（领袖模型专用）

贴图侧的五道闸门来自今汐工程 2026-11 定稿。贴图整包重建、掩膜替换、局部调色三类动作都按本文执行；渲染与动画侧的判据见 `acceptance.md`。

## 一、判据一：基色的来源只能是漫反射

UE 素材的贴图后缀语义：

| 后缀 | 内容 | 能否当 BaseColor |
| --- | --- | --- |
| `_D`、`_D2`、`_D3` | 漫反射（颜色） | 能，且只有这一族能 |
| `_N` | 法线 | 不能 |
| `_LD`、`_M`、`_HM` | 明度图、掩膜、高光掩膜 | 不能 |
| `_VC` | 顶点色 | 不能 |
| `_ID` | 编号图 | 不能 |
| `_SDF` | 距离场（装饰件） | 平滑项可以当颜色，需目视确认 |

数值指纹（统一缩放到统计基准尺寸后按亮度统计；统计口径与出图档位无关）：

| 类型 | 最小 | 均值 | 暗像素占比（<128） |
| --- | --- | --- | --- |
| 漫反射 | 80～90 | 160～190 | 5%～15% |
| 明度图 | 60～70 | 90～120 | 接近 100% |
| 近黑掩膜 | 20～30 | 55～65 | 95% 以上 |
| 法线图 | — | 围绕 128 窄分布 | — |

同源判定：把候选缩放到与工程既有同槽贴图同尺寸，逐像素算相关系数，取分块相关中位数最高者。今汐实测：头发基色 `Hair_D` 与工程既有图相关系数 1.0（完全同源），`Hair_LD` 为 0.74、`_HM` 0.77、`_VC` 0.08。

反向证据（会写进案例的错误做法）：把 `_LD` 乘 1.99 当基色，得到最小 132、均值 185、暗像素 0% 的过曝图，发丝层次与暗部一起消失。

## 二、判据二：掩膜 DDS 的头字段决定材质是否显示

材质 `Opacity` 槽绑了贴图，这张贴图的 DDS 头字段不符时，整块几何在引擎里不出现，cook 不报错。

| 字段 | 合规值（工程既有掩膜） | 会出错的取值 | 后果 |
| --- | --- | --- | --- |
| `pixelformat.dwFlags`（偏移 80） | `0x40`（DDPF_RGB） | `0x20000`（DDPF_LUMINANCE） | 整块几何不渲染 |
| `caps`（偏移 108） | `0x401007` | `0x401008` | 同上 |
| 尺寸 | 256² 掩膜 | 任意 | 与既有掩膜一致即可 |

复核命令：`python scripts/probes/dds_tex_verify.py <dds...>` 打印偏移 80／108 的取值与白度；与工程内既有掩膜逐项比对，不一致不得进入 cook。

反向证据：今汐头发掩膜由工具链生成时取到 `0x20000`／`0x401008`，头发整块消失；仅把这两个字段改回 `0x40`／`0x401007`（负载逐字节不动，87,509 字节）即恢复显示。

### 单位链没有 `Opacity` 槽

上面这一整套只对领袖成立。单位材质（`m_ClassName=Unit`）的参数表只有 11 项，没有 `Opacity`；`Leader_Matte` 与 `Generic_OPAC` 都绑不上去，cook 直接拒绝。单位上的轮廓必须由几何给出，做法与三次错位成因见 `references/case-unit-surface-patch.md`。

### 全透明像素必须清零 RGB

透明像素的 RGB 引擎照画。蒙版切图后若透明区还留着底色，贴片四周会出一圈彩色毛边，颜色就是残留底色。御三家的 `MI_3XingStar_BaseColor.dds` 是干净样本：60,092 个 alpha 为 0 的采样点全部 RGB 为 0。

判据用 `scripts/unit/alpha_rgb_audit.py`，退出码 0 即干净：

```
python scripts/unit/alpha_rgb_audit.py <png 或 dds>... --stride 4
```

清理只需把 alpha 为 0 的像素 RGB 置 0，alpha 非零的像素逐字节不动。

**作用域（2026-11-03 补）**：这条只适用于蒙版贴片、星芒、轮廓贴花这类"整张图就是一张镂空图"的槽。**领袖基色不适用**——`Leader_Matte` 直出 BaseColor，透明区 RGB 就是最终颜色，置 0 会在岛内洞里留下黑块：黑布恰好看不出，浅色布料会出黑斑。领袖基色的落色口径见 `leader-pipeline.md` §5.4，两处冲突时以 §5.4 为准。

## 三、判据三：局部贴图修改必须由 UV 岛定位

颜色阈值与形态学定位会同时圈中图集空白区、双马尾发尾和浅色缎带，今汐实测被用户退回三次。定位必须来自模型自身的 UV：

1. 用 Blender 无头导出「主导骨骼 → UV 三角」表：

```bash
export BLENDER_USER_RESOURCES='E:\SoftWares\blender45\userres'
"<Blender>" -b --python scripts/probes/dump_hair_uv.py
```

脚本按面的主导顶点组（权重和最大者）分组，只取目标材质槽的面，逐面三角化后写 `<方案根>/workspace/tmp/<wp>/hair_uv.tsv`，字段为 `组名 u1 v1 u2 v2 u3 v3`（v 轴按 1−v 翻转成贴图像素行）。

2. 用 PIL 把三角栅格化成与出图档位 `TARGET_SIZE` 同尺寸的掩膜，再与颜色判据相交；掩膜外一律不动。掩膜尺寸必须随 §五 的自适应档位走，不固定 1024²。

> **行序不变式（2026-11 长离事故后新增，唯一正确写法）**：图像第 0 行是图像**顶部**，对应 v=1；UV 的 v 自下而上。所以 texel 行号必须是 `row = (1 − v) × H`。写成 `row = v × H` 会把掩膜上下翻转，且**不报错、不过界、文件合法**——是纯静默失败。
>
> 失败特征：翻转后掩膜只覆盖真实足迹的一部分，实测 6.4% 的 texel 仍保持半透明 → 被 `0.3333` 裁掉 → 实机额发偏浅、与 Blender 参考出现明显色差，而 Desktop 侧一切正常。判据：掩膜 α=255 的 texel 数与面集投影面积吻合；把掩膜与 UV 岛叠图后边界逐像素贴合，出现上下镜像即行序错。
>
> **排查顺序（别先怀疑模型）**：先逐值比对源模型与工程 cn6 的 UV（长离 40,269 loops，max 差值 0.0000 —— 逐值相同即证明几何与 UV 无责），再查掩膜行序。跳过这一步会去改模型，改不动，还引入新缺陷。
>
> **工具**：`python scripts/probes/mask_roworder_audit.py --mask <png> --uv workspace/tmp/<wp>/hair_uv.tsv`。它用同一份 UV 三角按两种行序各栅格化一次，比岛内覆盖率：退出码 `0` = 正写、`4` = 已翻转、`5` = 判不出（掩膜近似上下对称时必然报判不出，别当通过）。自带 `--selftest` 反向闸门（注入翻转必须报 `MIRRORED`）。

3. 与颜色判据相交后的掩膜必须出预览图（品红覆盖）并留档，预览里出现图集空白区、发尾条带、缎带条带即为定位错误，停下重做。

骨骼分组表随角色而异，按主导骨骼导出后逐组核对面数与 UV 跨度即可。分组判断出过一次错：两侧垂发的一二段被当成双马尾，漏掉这两组时垂发中段一直留灰，所以分组表必须一直覆盖到发尾末节。

鸣潮角色的骨骼分组实测表（面数／UV 范围／平均高度）见 `references/wuwa-notes.md` 第五节 <!-- WUWA -->

## 四、判据四：色块与渐变的取舍

- 整片替换成基色（阈值切块 + 羽化）会得到平涂，适合纯灰块：`L ≤ 125` 全替换、125～150 线性羽化。
- 保留层次的做法是平滑曲线压缩：`L' = 208 + 0.22 × (L − 208)`，再按 `基色 × (L'/205)` 上色。整片同一条连续曲线，没有阈值边界，所以不出现色块。今汐定稿用这一条，系数 `0.22` 是唯一调节量。
- 保亮度的换色（`基色 × L/205`）只改色相不动明度，适合“颜色族不对、明暗还要留”的部位。

## 五、判据五：自适应分辨率档位、预览先于 cook

**口径：出图尺寸随源图自适应，默认取源图原尺寸（鸣潮角色 `_D` 通常为 2048²），不做静默降采样。** `Leader_BaseColor` 类别 `max_width/max_height = 4096`、`require_pow2 = true`，2048² 与 4096² 均为合法档位；早期把出图尺寸写死 1024²、并把分辨率变化当作风险的做法已作废。

出图档位由单一参数 `TARGET_SIZE` 决定，以下三处必须逐项一致：

| 项 | 算法 / 取值 |
|---|---|
| 源图 | 只取 `_D` 族原尺寸；若确需降档，必须显式写出「源尺寸 → 目标尺寸」的倍率并留痕，禁止默认缩放 |
| DDS | `size = TARGET_SIZE`；`mips = TARGET_SIZE.bit_length()`（2048→12、1024→11）；未压缩 `R8G8B8A8_UNORM`，mip 链用 BOX 逐级重建 |
| `.tex` | `<m_Width>` / `<m_Height>` 写 `TARGET_SIZE`，`<m_NumMipMaps>` 写 `mips`，与 DDS 头逐项比对 |
| 掩膜 / 预览 | UV 三角栅格化掩膜与预览图都用 `TARGET_SIZE`，不固定 1024² |

实现参考（按 `size` 参数化、mip 与 `.tex` 同步的自适应写法）：`dds_basecolor(name, png, size)` 用 `mips = size.bit_length()`，`write_tex(path, ..., size, size, mips)` 同步改写 W/H/mips —— 这类「后面加的自适应」实现是本判据的基准；早期 `make_basecolor()` 里 `resize((1024, 1024))` + 固定 `-m 11` 的写法属旧档位，新工程不得照抄。

**验收闸门**：`源图尺寸 → DDS 头 W/H/mips → .tex W/H/mips` 三处一致，任一不符即停止。`scripts/probes/dds_tex_verify.py` 与 `texpair_check.py` 按 `texture-classes.json` 的类别上限校验，2048² 不会报尺寸越界。

**关于 `falling back to uncompressed`**：这条回退只与「DDS 尺寸 / 像素格式与 `.tex` 声明不一致，或同槽内尺寸混杂」有关，与 2048 本身无关。今汐早期单槽 Eye 改动（1024²→2048²）体积由 18,819,584 增至 19,474,944 字节并回显回退，是尺寸未同步 `.tex` / mip 的条件性案例。反证：御三家工程六张 2048² / 12 mip BaseColor 的 `.tex` 全部同步 `2048/2048/12`，三包 cook `COOK_EXIT=0`、九类告警全 0、`falling back` 零命中。**全槽统一升档 + 三处一致是已验证路径**；BLP 体积随分辨率上升属预期（2048² 未压缩 RGBA 单张 21.33 MB，1024² 为 5.33 MB），不是故障。

贴图写完先跑一次预览，通过才 cook：

```bash
cmd /c "set BLENDER_USER_RESOURCES=E:\SoftWares\blender45\userres && <Blender> -b --python E:\SoftWares\blender45\open_model.py -- "<方案根>/<工程名>/workspace/gen/<代号>/<模型>.cn6""
```

判据：输出末行 `OPEN_MODEL_OK`。今汐四轮无效改动各付了一次完整 cook 与部署，第四轮起改为先预览后 cook。

## 六、汇报格式

每轮贴图改动必须给出：参与像素数与占比、整图最小／均值／标准差、两个阈值（`<128`、`<175`）的暗像素占比、掩膜预览路径、dds 字节数与 sha256 前 16 位、是否 cook 与部署。
